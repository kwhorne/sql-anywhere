# SQL Anywhere contracts for TypeScript

The [storage contracts](../../docs/contracts/README.md) (a durable queue, a
KV cache with TTL and locks, pub/sub over an event log) as a typed TypeScript
API. The modules in `src/` are generated by `cargo xtask gen-contracts` from
the same documents as the Rust and [PHP](../php/README.md) APIs, and CI fails
when a document changes without them, so the SQL here is always the
contract's own.

```ts
import { createClient } from "@libsql/client";
import { cache, fromLibsql, pubsub, queue } from "@sqlanywhere/contracts";

const db = fromLibsql(createClient({ url: "http://127.0.0.1:8080" }));   // sqld, or file:app.db
await queue.install(db);                                              // once, like a migration

const { id } = await queue.enqueue(db, { queue: "mail", payload, priority: 0, delay: 0, maxAttempts: 25 });
const job = await queue.claim(db, { visibility: 30, queue: "mail" });  // { id, payload, … } or null
if (job) await queue.ack(db, { id: Number(job.id) });

await cache.set(db, { key: "user:7", value: json, expiresAt: Date.now() / 1000 + 300 });
const lock = await cache.lock(db, { key: "import", owner: hostname(), ttl: 60 });   // null when held

await pubsub.publish(db, { channel: "orders", payload: event });
for (const e of await pubsub.subscribe(db, { channel: "orders", cursor: last, batch: 100 })) { /* e.seq, e.payload */ }
```

- One module per contract (`queue`, `cache`, `pubsub`): `install()`,
  `VERSION`, `SCHEMA`, the SQL of every operation as a constant, and one async
  function per operation taking a `Driver` and an object of the operation's
  parameters, typed from the contract's parameter table. Nullable parameters
  may be left out.
- Rows come back as objects keyed by column name. `:exec` operations return
  the number of rows changed, `:opt` ones `null` when there is no row, and
  `:one` ones throw when there is none.
- An operation of several statements (dead-lettering a job, invalidating a
  tag) runs them in one transaction through `Driver.batch`, `BEGIN IMMEDIATE`
  where the contract says so, and rolls back if one fails. That works over
  HTTP too, where separate `BEGIN` and `COMMIT` requests would not.
- Payloads and cache values are blobs: pass a `Uint8Array`, or a string, which
  is stored as its UTF-8 bytes. They come back as `Uint8Array`.

## Drivers

The package has no runtime dependencies. A `Driver` runs a statement, and a
list of them in one transaction; two adapters are included, each typed by the
few methods it calls, so neither client is a dependency:

| Adapter | For |
| --- | --- |
| `fromLibsql(client)` | `@libsql/client`: a `sqld` server over HTTP, or a local file |
| `fromNodeSqlite(db)` | `node:sqlite`'s `DatabaseSync`: a local file, no packages at all |

## Development

Requires Node 22.18+, which runs the TypeScript sources directly.

```sh
npm ci
npm run typecheck
npm test                                        # node:sqlite and @libsql/client on files
SQLD_URL=http://127.0.0.1:8080 npm test         # the same checks against a running sqld
npm run build                                   # dist/, for publishing
```

CI runs the type check, the tests and the build on Node 22 and 24
(`.github/workflows/typescript-client.yml`).
