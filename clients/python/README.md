# SQL Anywhere contracts for Python

The [storage contracts](../../docs/contracts/README.md) (a durable queue, a
KV cache with TTL and locks, pub/sub over an event log) as a typed Python
API. The modules in `sqlanywhere_contracts/` are generated by
`cargo xtask gen-contracts` from the same documents as the Rust,
[PHP](../php/README.md) and [TypeScript](../typescript/README.md) APIs, and CI
fails when a document changes without them, so the SQL here is always the
contract's own. No dependencies: the standard library is enough.

```python
import sqlite3
from sqlanywhere_contracts import cache, from_sqld, from_sqlite3, pubsub, queue

db = from_sqld("http://127.0.0.1:8080")                    # a sqld server, or:
db = from_sqlite3(sqlite3.connect("app.db", isolation_level=None))
queue.install(db)                                           # once, like a migration

job_id = queue.enqueue(db, queue="mail", payload=body, priority=0, delay=0, max_attempts=25)["id"]
job = queue.claim(db, visibility=30, queue="mail")         # {"id": …, "payload": b"…", …} or None
if job:
    queue.ack(db, id=job["id"])

cache.set(db, key="user:7", value=json_text, expires_at=int(time.time()) + 300)
lock = cache.lock(db, key="import", owner=socket.gethostname(), ttl=60)   # None when held

pubsub.publish(db, channel="orders", payload=event)
for e in pubsub.subscribe(db, channel="orders", cursor=last, batch=100):
    ...                                                     # e["seq"], e["payload"]
```

- One module per contract (`queue`, `cache`, `pubsub`): `install()`,
  `VERSION`, `SCHEMA`, the SQL of every operation as a constant, and one
  function per operation taking a `Driver` and the operation's parameters as
  keyword arguments, typed from the contract's parameter table. Nullable
  parameters default to `None`.
- Rows come back as dicts keyed by column name. `:exec` operations return the
  number of rows changed, `:opt` ones `None` when there is no row, and `:one`
  ones raise `LookupError` when there is none.
- An operation of several statements (dead-lettering a job, invalidating a
  tag) runs them in one transaction through `Driver.batch`, `BEGIN IMMEDIATE`
  where the contract says so: each statement runs only if the one before it
  succeeded, and nothing is kept if one fails. Over HTTP that is a single
  Hrana batch request, where separate `BEGIN` and `COMMIT` requests would not
  hold.
- Payloads and cache values are blobs: pass `bytes`, or a `str`, which is
  stored as its UTF-8 bytes. They come back as `bytes`.

## Drivers

A `Driver` runs a statement, and a list of them in one transaction; two are
included:

| Driver | For |
| --- | --- |
| `from_sqld(url, auth_token=None)` | a `sqld` server over HTTP (Hrana's `/v2/pipeline`), with `urllib` |
| `from_sqlite3(conn)` | the standard library's `sqlite3`: a local file. The connection must be in autocommit mode, `isolation_level=None`, or `sqlite3` keeps its own transactions open and nothing is committed |

A statement `sqld` refuses raises `SqldError`, with the SQLite error code in
`.code`. The operations need SQLite 3.35 or later (`RETURNING`), which every
supported Python ships.

## Development

Requires Python 3.9 or later.

```sh
python -m unittest discover -s tests                                   # sqlite3
SQLD_URL=http://127.0.0.1:8080 python -m unittest discover -s tests    # and a running sqld
```

CI type-checks the package with `mypy --strict`, runs the tests on Python 3.9
and 3.13, and installs the package (`.github/workflows/python-client.yml`).
